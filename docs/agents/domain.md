# Domain Docs

This is a single-context project. Before exploring an area, read the root `GLOSSARY.md` if it exists and relevant decisions in `docs/adr/`. If either is absent, proceed without flagging it; create domain documentation only when terminology or a decision needs to be recorded.

Use glossary terms consistently in issues, proposals, and tests. If a needed term is missing, reconsider whether the project language is clear or record the gap for domain modeling. If proposed work conflicts with an ADR, call out the conflict rather than silently overriding it.

Expected layout:

```text
/
|-- GLOSSARY.md
`-- docs/adr/
```
