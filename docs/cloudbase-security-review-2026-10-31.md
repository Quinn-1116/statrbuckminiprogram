# CloudBase 部署前安全审查（2026-10-31）

## 结论

**代码层部署阻塞已修复，但仍不能直接面向用户开放。** 两个云函数尚未部署到 CloudBase，也没有真实账号联调；本地测试和 SDK 初始化检查不证明云端身份、权限规则、数据库行为或微信登录配置正确。本文没有访问或修改云端资源。

## 必须先解决

1. **数据库 SDK 契约不匹配（已修复，待云端验证）**：已将 `set/update` 改为 SDK 实际接受的数据对象，客户档案读取兼容 SDK 的文档返回形状，并新增回归测试。仍需在真实 CloudBase 环境验证。
2. **订单文档 ID 与业务 ID 不一致（已修复，待云端验证）**：订单改为用业务 `order.id` 调用 `.doc(id).set(order)`，状态更新使用同一文档 ID，并新增创建后更新测试。仍需验证重复请求和真实事务行为。
3. **调用者身份及授权链未经过真实验证（云端阻塞）**：`order-api` 现通过 Node SDK `auth().getAuthContext(context)` 读取本次调用的认证用户，订单以认证上下文中的 CloudBase `uid` 隔离；微信 OpenID 是自定义票据的 `customUserId`，不假设它与 CloudBase `uid` 相等。管理员 `ADMIN_UID` 必须由真实管理员登录态核对。仍需用两个真实客户、管理员、匿名调用及伪造请求字段验证隔离和拒绝行为。
4. **依赖安全（本地已修复，待部署包复核）**：两个函数都使用 `@cloudbase/node-sdk@4.2.1`，将 SDK 精确固定的 axios 覆盖到 `1.21.0`；Node SDK 4.2.1 保留 `createTicket`、`getAuthContext(context)` 和 `database()` API。两函数在 2026-10-31 对各自生产依赖执行 `npm audit --omit=dev --json` 均为 0 项。上述 API 形状已做本地 smoke test；仍须在最终部署目录复核 `npm ci` 和 audit，部署包不应包含 `.env` 或密钥。
5. **数据库规则和调用权限未验证（阻塞）**：部署前必须给 `orders`、`customers` 配置拒绝客户端直接读写的规则，并以不同登录态实测；确认登录票据函数可在未认证状态按预期调用，同时限制滥用。不能仅依赖前端隐藏管理功能。
6. **订单查询完整性和资源限制（分页本地已修复，频率控制待云端）**：下单最多 50 个购物车行、100 杯总量；微信身份交换有 5 秒超时、HTTP 状态码校验和 8KB 响应上限。`listMine` 和 `listAll` 现采用固定 50 条页面、额外读取 1 条判断是否有下一页，并用排序字段与 `_id` 稳定排序；小程序和管理端均可加载更多。当前用 `skip` 偏移分页，私测量级适用；并发插入期间翻页仍可能出现重复或遗漏，扩大用户规模前应换成经 CloudBase 验证的 keyset 游标。匿名可调用的登录票据函数限频仍需在 CloudBase 配置并验证。

## 部署清单（修复与验证之后）

- 部署前在 Node 20 最终包目录运行 `npm ci`、`npm audit --omit=dev`，并对比本地锁文件；全量单元测试及函数/管理端构建需通过。
- 检查两个云函数的依赖锁文件，评估审计结果，确认构建产物与生产依赖的部署目录及入口；避免打包凭证、`.env`、测试数据。
- 确认环境 ID、运行时、调用权限、数据库安全规则和资源限额；当前没有云端部署或规则变更授权。
- 微信 AppSecret 和自定义登录私钥仅在安全配置入口录入，不写入仓库、日志或聊天；确认可信域名、管理员账号和真实 UID。不要把环境 ID 或 AppID 当作密钥。
- 真实联调需两个客户与管理员：核对跨账号订单隔离、管理员权限、拒绝直接数据库访问、订单状态变化和费用使用；联调产生的数据须明确标记。
