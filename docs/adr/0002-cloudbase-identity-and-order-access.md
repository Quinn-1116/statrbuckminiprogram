# CloudBase identity and shared order access

The mini program and management web page use CloudBase as their shared order data source, with server-enforced access rules: a one-time WeChat login code is exchanged server-side for a CloudBase custom-auth ticket using the verified OpenID as `customUserId`. Authorization and customer ownership use the authenticated CloudBase `uid`; it must not be assumed to equal the OpenID. Cloud functions use the Node SDK request context for identity; do not replace it with process-global user state. Management access uses one developer-provisioned administrator account with no public registration and credentials kept outside the repository. Customer history queries are constrained by the authenticated CloudBase UID; administrator access is an explicit UID allowlist check whose value must be verified from a real administrator session. Local mock identity and separate mock order stores are for flow development only; they do not satisfy privacy or cross-client synchronization acceptance. Start in a personal trial environment, verify current pricing and resource limits, and obtain explicit approval before enabling any potentially paid service. Deployment remains blocked until the required secrets and CloudBase permissions are configured, and real account isolation is verified.
